## 4. 首版奖励规则

以下为首轮试玩参数，应集中配置，儿童实测后再调整。

| 奖励 | 触发条件 | 燃料 | 唯一事件 ID 示例 |
|---|---|---:|---|
| 认声音 | 本课森林全部字母完成 | 30 | `lesson:mission-001:forest` |
| 拼读 | 本课全部拼读题通过 | 20 | `lesson:mission-001:dunes` |
| 口语 | 本课口语完成正式提交 | 30 | `lesson:mission-001:crystal` |
| 整课完成 | 本课三个阶段全部完成 | 10 | `lesson:mission-001:complete` |
| 合计 | 完成一课 | **90** | 四个事件各记一次 |

第一课的商店剧情结束、领取苹果或宝石不单独发燃料；点击「完成对话，点亮星球」时才满足口语奖励条件。第二、三课沿用家长确认口语完成。使用提示或家长协助不降低奖励。

整课奖励直接依据现有完成状态派生，不增加一个为了领奖而重复点击的总结流程。复习、重放音频、重玩商店和再次完成旧课均不重复发放这四类奖励。独立复习机制未实现前，不加入原设计中的复习 +10。

### 4.1 旧记录补发

1. 先使用既有校验逻辑恢复 v1/v2/v3 记录，保留有效课次、草稿、音量和对话状态。
2. 按每课有效阶段完成情况生成奖励事件；只补当前账本中没有的事件。
3. 旧版口语完成继续有效，不强迫重做宇宙商店；旧版森林第四步示范不能算作沙丘完成。
4. 迁移完成后再次加载不会再次发放奖励。
5. 三课全部完成的旧记录最多补发 270 燃料；仅第一课森林完成的记录补发 30。

## 5. 探索路线与费用

首版采用推荐顺序路线。新地点需满足前置发现条件与燃料要求；后续可扩展自主选择分支。

| 目的地 | 前置地点 | 首次费用 | 主要内容 | 收藏反馈 |
|---|---|---:|---|---|
| 地球 | 无 | 0 | 初始飞船、出发目标、地球科普卡 | 起点图鉴 |
| 轨道空间站 | 地球 | 50 | 与机器人准备补给，复用已学问候和感谢表达 | 空间站图鉴、补给标记 |
| 月球 | 空间站 | 100 | Go / Stop / Jump 点按指令互动，可重复尝试 | 月球图鉴、旗帜 |
| 火星 | 月球 | 120 | 按提示点按搭建预设小基地，练习 I need a block. | 火星图鉴、基地组件 |

空间站首版设为虚构补给设施，名称与标注不得暗示它就是国际空间站。真实天体、虚构设施和游戏互动分别说明。科普卡中的事实需在内容制作时核验可靠来源，记录来源、核验日期及图片许可。

前三课奖励总计 270，首次航行总费用为 50 + 100 + 120 = 270。首课结束后可以抵达空间站；前两课结束后可以累计抵达月球；三课结束后可以抵达火星。旧地点免费回访，不因回访改变下一未发现地点的费用。

发现地点即开放后续航点的前置条件，地点英语互动单独记录完成情况，不增加惩罚性航行门槛。首次发现奖励只包含图鉴或收藏，首版不额外发燃料，避免经济曲线出现隐藏来源。

## 6. 页面和交互

### 6.1 航行页

顶部保留返回学习、声音与家长入口。主体优先呈现飞船当前位置、四个目的地及当前选择。底部只突出下一站、费用/缺口和「起飞」或「去学习」主按钮。

状态需同时用图像、图标与简短文字表达：当前位置、已到达、下一站、未开放。已到达地点显示「免费回访」。燃料不足时显示还差多少，不制造倒计时、连胜或连续登录压力。

按用户最新要求，统一使用一张全宇宙概览地图：长期方案的 62 个节点全部收录，分六大星域切换，加上现有虚构补给站共 63 个地点。所有节点可查看详情，未开发节点标注筹备中；未定费用不编造数字。仅地球和补给站提供实际航行。

节点详情先显示图片或原创示意图，再显示与地球的距离、大小或与太阳的比较和一句简介，最后保留航行状态与费用。科学资料和图片配置集中在 `src/data/space/science.ts`、`src/data/space/images.ts`，本地文件在 `public/space-images/`；页面运行不依赖第三方图片请求，加载失败回退到示意图。

图片按真实观测能力和内容标注，不统一称为「真实照片」。遥远恒星通常只是光点；妊神星使用哈勃观测图；比邻星 b 为艺术家想象图；日球层顶为科学示意图；奥尔特云展示相关彗星观测；人马座 A* 展示银河系中心相关区域观测图。虚构补给站和月球轨道站、轨道位置没有真实照片。来源、署名和许可在弹窗可查，原始下载地址保存在 `artifacts/science-research/images.json`。科普数字与素材许可仍待逐条人工终审。

### 6.2 航行动画与抵达

- 起飞前再次检查燃料、前置地点、当前事务状态。
- 一次状态提交中扣除燃料、记录首次发现与当前位置、写入交易和收藏记录。
- 动画只是成功提交后的呈现，不决定是否扣费或发奖。重复点击不能再扣费。
- 动画中刷新后直接显示已抵达状态；减少动态效果模式可跳过过场。
- 抵达后提供简短科普卡、地点互动入口和返回航线入口。

### 6.3 地点互动与图鉴

每处重要地点都需有可操作内容，不能仅显示一条恭喜。空间站优先复用现有对话配置和提示机制；扩展复用能力时避免重写第一课商店。

图鉴采用简单卡片，包含中英文名称、类别、事实、收藏状态及免费回访入口。科普与游戏想象明确区分，地图注明非真实比例。火星基地采用固定步骤点按搭建，首版不做自由拖动或复杂建造资源系统。

### 6.4 存档导入与导出

放在家长面板，导出包含版本和完整学习/探索进度的 JSON。导入前检查版本、大小、类型、节点 ID、事件唯一性和余额一致性，并展示摘要。用户确认覆盖后才替换当前存档，提供先导出现有记录的入口。

首版采用完整替换，不做两份存档的奖励合并，防止重复叠加燃料。损坏、未知版本或不一致账本不得静默覆盖有效存档。导入完成后只根据导入记录补齐缺失的合法奖励事件。

## 7. 数据与代码组织

### 7.1 状态设计

计划内部版本升级到 v4，继续沿用原存储键。保留现有课程进度结构，在顶层增加探索状态；探索数据不放入某一课的归档字段。

```ts
// 设计示意，具体类型在实施时与现有 Progress 整合。
type SpaceProgress = {
  currentNodeId: string;
  discoveredNodeIds: string[];
  completedMissionIds: string[];
  collectedItemIds: string[];
  firstArrivedAt: Record<string, string>;
  shipLevel: 1;
  transactions: SpaceTransaction[];
};

type SpaceTransaction = {
  eventId: string;
  kind: 'learning_reward' | 'first_travel';
  sourceId: string;
  amount: number; // 收入为正，航行支出为负
  createdAt: string;
};
```

燃料余额由已验证交易求和派生，避免同时维护两个独立余额。事件 ID 不以时间戳生成：阶段奖励按课程与阶段固定，首次航行按目的地固定，例如 `travel:moon:first`。历史交易保存实际金额，调整未来参数不能追溯改写已有余额。

`discovered` 与 `completedMissionIds` 分别表示到达和互动完成。图鉴收藏、商店苹果/宝石和未来建造材料分别管理，不把第一课补给兑换成燃料。

### 7.2 持久化与故障

学习进度、奖励事件与航行状态使用同一个完整存档提交。存储失败不能显示保存成功：学习仍可进行，明显提示进度未可靠保存；航行提交失败时不播放成功抵达反馈，保留之前的有效探索状态并允许重试。

前端本地存档无法提供服务端级防作弊，首版只保证正常操作下幂等和数据一致。多标签页不得同时覆盖旧快照：写入前检查存档修订号，发生冲突时提示重新载入；如支持多标签页同时写入，必须采用可串行化写入方案并验证目标 Safari 的兼容性，不能将单纯的读后写比较当作跨标签原子锁。

## 9. 验收场景

| 场景 | 预期结果 |
|---|---|
| 全新用户 | 地球起点，0 燃料，基础学习始终可进入 |
| 只完成第一课森林 | 30 燃料，去空间站仍差 20 |
| 第一课全部完成 | 总奖励 90，抵达空间站后余 40 |
| 前两课全部完成 | 总奖励 180，累计抵达月球后余 30 |
| 前三课全部完成 | 总奖励 270，累计抵达火星后余 0 |
| 重玩课程或商店分支 | 原学习奖励和收藏不重复累计 |
| 迁移旧三课完成记录 | 补发 270，后续刷新仍为同一账本 |
| 燃料不足或前置未到达 | 无法起飞，余额与发现记录不变 |
| 双击起飞、动画中刷新 | 只扣一次，恢复到已抵达地点 |
| 免费回访 | 不改变余额，不重复发首次发现奖励 |
| 存储写入失败 | 不伪报保存或抵达成功，提供可理解提示 |
| 导入损坏或未知版本文件 | 保留当前有效存档，不覆盖、不增加燃料 |
| 两个标签页修改 | 不静默覆盖进度或生成重复交易 |
