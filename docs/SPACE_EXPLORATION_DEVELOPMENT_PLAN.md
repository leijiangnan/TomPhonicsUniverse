## 2. 当前基础与首版边界

现有工程已提供前 16 课、逐课解锁、每课三个学习阶段、第一课宇宙商店对话和电脑后台统一存档。本方案制定时内部进度为 v3；当前为 v4，旧浏览器键 `tom-phonics-progress-v1` 仅供一次性读取迁移。正式存档在 `.data/progress.sqlite`，iPad 与电脑连接同一后台时共用进度。

原四地点目标包括以下内容；当前已实现 9 航点导航、补给站互动、学习奖励与后台备份，月球指令游戏、火星和完整图鉴仍待开发：

- 学习奖励与燃料余额；对已有有效学习记录一次性补发。
- 地球、空间站、月球、火星四个可操作地点。
- 航行页面、短抵达动画、免费回访、科普卡和收藏。
- 空间站补给互动、月球指令游戏、火星点按建造互动。
- 家长面板中的存档导出与导入。

尚不实现：全部 62 个方案节点的航行与互动、10–15 个节点的完整首批玩法、多级引擎升级、自由建造、复杂背包、复习燃料奖励、云同步与独立奖励中心。目录与科普预览已收录，不能将「可以查看」等同于「可以航行」。四地点版本验收后再决定后续互动扩展。

## 4. 首版奖励规则

以下为首轮试玩参数，应集中配置，儿童实测后再调整。

| 奖励 | 触发条件 | 燃料 | 唯一事件 ID 示例 |
|---|---|---:|---|
| 认声音 | 本课森林全部字母完成 | 30 | `lesson:mission-001:forest` |
| 拼读 | 本课全部拼读题通过 | 20 | `lesson:mission-001:dunes` |
| 口语 | 本课口语完成正式提交 | 30 | `lesson:mission-001:crystal` |
| 整课完成 | 本课三个阶段全部完成 | 10 | `lesson:mission-001:complete` |
| 合计 | 完成一课 | **90** | 四个事件各记一次 |

第一课商店领取苹果或宝石不单独发燃料，正式提交水晶星完成才满足口语奖励条件。第 2–16 课按各自单句或复习场景的家长确认完成；使用提示或家长协助不降低奖励。轻复习、声音与音乐控制均不产生奖励事件。

整课奖励直接依据现有完成状态派生，不增加一个为了领奖而重复点击的总结流程。复习、重放音频、重玩商店和再次完成旧课均不重复发放这四类奖励。独立复习机制未实现前，不加入原设计中的复习 +10。

### 4.1 旧记录补发

1. 先使用既有校验逻辑恢复 v1/v2/v3 记录，保留有效课次、草稿、音量和对话状态。
2. 按每课有效阶段完成情况生成奖励事件；只补当前账本中没有的事件。
3. 旧版口语完成继续有效，不强迫重做宇宙商店；旧版森林第四步示范不能算作沙丘完成。
4. 迁移完成后再次加载不会再次发放奖励。
5. 字母启航 8 课全部完成最多获得 720 燃料；旧三课完成记录仍补发 270，仅第一课森林完成的记录补发 30。

当前按全宇宙概览的地月空间顺序开放全部 9 航点。价格是游戏学习参数，不模拟真实航程；不改变已产生的历史补给站 -50 事件。

|---|---|---:|
| 地球 | 无 | 0 |
| 补给空间站 | 地球 | 50 |
| 国际空间站 | 补给空间站 | 50 |
| 月球 | 国际空间站 | 100 |
| 月球背面 | 月球 | 40 |
| 地月 L2 点 | 月球背面 | 40 |
| 月球轨道空间站 | 地月 L2 点 | 60 |

费用与稳定 ID 集中在 `src/data/space/route.ts`，`src/lib/space.ts` 负责检查顺序、余额和事件去重。恢复时按目录验证合法扣费，不接受跳站或无效金额；备份与后台同样校验。未来调整参数时须另做规则版本和账本迁移，不能直接修改表格重算历史余额。旧四地点草案中的火星 120 不作为本轮扣费配置。

补给空间站、游戏月球轨道站和太阳观测站为虚构设施，与真实国际空间站区分；轨道位置和观测航点不表示实际登陆。原四地点目标中的月球 Go / Stop / Jump 与火星搭建任务仍待后续授权实施。当前不因发现或回访额外发放燃料。

## 6. 页面和交互

### 6.1 航行页

顶部保留返回学习、声音与家长入口。首屏航行控制台先显示操作区，再展示 3D 场景。以「下一个新航点」区分未发现目标，主操作明确显示「前往目的地名称」，燃料不足时显示缺口及学习入口；补给站收藏作为次要操作保留。首屏同时提供「免费回访」图片选择，已发现地点无需补足新航点燃料即可免费往返；返回地球不重置发现状态。节点详情原有回访入口与控制台免费返回地球继续保留。下方完整星图显示真实已到达数量，9 点全部到达后仍可回访。

状态需同时用图像、图标与简短文字表达：当前位置、已到达、下一站、未开放。已到达地点显示「免费回访」。燃料不足时显示还差多少，不制造倒计时、连胜或连续登录压力。

按用户最新要求，统一使用一张全宇宙概览地图：长期方案的 62 个节点全部收录，分六大星域切换，加上现有虚构补给站共 63 个地点。所有节点可查看详情，未开发节点标注筹备中；未定费用不编造数字。地月空间 9 点提供实际航行，其余五个星域仍标注筹备中。节点详情的航行按钮置于科普内容之前，明确费用或锁定原因。

节点详情先显示图片或原创示意图，再显示与地球的距离、大小或与太阳的比较和一句简介，最后保留航行状态与费用。科学资料和图片配置集中在 `src/data/space/science.ts`、`src/data/space/images.ts`，本地文件在 `public/space-images/`；页面运行不依赖第三方图片请求，加载失败回退到示意图。

图片按实际内容标注，不统一称为「真实照片」。遥远恒星通常只是光点；比邻星 b 当前使用用户提供的轨道关系想象图，奥尔特云使用用户提供的中文太阳系外围示意图，人马座 A* 使用银河系中心相关区域观测图。虚构补给站采用真实商业补给飞船照片作参考，游戏轨道站和轨道位置使用概念图或示意图，不能把参考图片当成游戏设施的实拍。逐图来源、署名、许可与当前图片性质以 `src/data/space/images.ts` 和详情弹窗为准；用户提供且来源未确认的图片保留该待确认状态。资料与素材许可仍待人工终审。

### 6.2 航行动画与抵达

- 起飞前再次检查燃料、前置地点、当前事务状态。
- 一次状态提交中扣除燃料、记录首次发现与当前位置、写入交易和收藏记录。
- 动画只是成功提交后的呈现，不决定是否扣费或发奖。重复点击不能再扣费。
- 动画中刷新后直接显示已抵达状态；减少动态效果模式可跳过过场。
- 抵达后提供简短科普卡、地点互动入口和返回航线入口。

### 6.3 近期交互优化与设计理由（已实现）

| 决定 | 实施方式 | 设计理由与边界 |
|---|---|---|
| 当前动作先于完整星图 | 控制台位于首屏，先显示停靠位置、燃料缺口和可操作入口，完整星域保留在下方 | 同时支持当前任务与远期探索兴趣；未实现地点只有详情，不制造可起飞假象 |
| 学习目标与探索状态分层 | 学习首页强调本课三站；完成第 3 课后在驾驶舱显示同一张地图 | 地图安装从已完成学习派生，不另存物品进度或发额外燃料；不把 48 课课程单元覆盖课内三阶段 |
| 背景可见但可控 | 三层蓝青、紫色云团和云带，移入视口并渐隐，窄屏保留层次；课堂强度降至 `0.38` 并静止 | 回应「只看到白点」的反馈；使用 CSS/SVG 保留统一画风和暂停能力，不据此宣称注意力已改善 |
| 声音入口给出明确反馈 | 喇叭打开声音面板，音乐主动开启、可暂停和重试，主音量仍在家长面板 | 区分点读开关与背景音乐，避免无播放时切换图标像没反应；音乐默认关闭、刷新不启动 |
| 视觉与音乐分别控制 | 所有原生弹窗暂停视觉；声音面板可试听，节点详情当前可继续音乐；系统减少动态效果不自动静音 | 按实际任务控制，不把所有视觉状态误用于音频；示范与录音始终优先 |
| 保持旧进度与账本可信 | 沿用 v4/原键，统一保存，备份校验后完整替换；主音量开启未提交则停止本次音乐 | 保护历史完成与余额，避免静音状态和实际发声不一致；手动备份不是云同步 |

星空偏好保存于可选 `preferences.ambientMotion`，预览修改只保留在预览内。音乐只在地图、总览和航行中按用户意图播放，音量为主音量的 20%；上课、录音、家长面板和后台暂停，主动暂停后不自动恢复，意图不写存档。完整状态矩阵见 [PRD 4.4](PRD.md#44-背景可见性与专注的取舍)、[4.5](PRD.md#45-声音入口与播放优先级)；设计依据汇总见 [PRD 13.1](PRD.md#131-本轮迭代的决定依据)。

### 6.4 地点互动与图鉴（部分已实现）

当前已实现补给站三轮点读、家长确认、收藏卡与恢复；9 个开放航点均可航行、回访和查看科普详情，尚无独立图鉴中心。本轮只扩展导航，不把月球指令游戏或其他英语任务标为已完成。扩展空间站等对话能力时复用已有配置与播放互斥，避免重写第一课商店。

图鉴采用简单卡片，包含中英文名称、类别、事实、收藏状态及免费回访入口。科普与游戏想象明确区分，地图注明非真实比例。火星基地采用固定步骤点按搭建，首版不做自由拖动或复杂建造资源系统。

### 6.5 存档导入与导出（已实现）

已放在家长面板，导出包含版本和完整学习/探索/复习进度的 JSON。导入检查版本、1 MB 大小上限、字段类型、课程先备条件、节点 ID、事件唯一性、金额和余额一致性，展示已完成课数、当前课次、燃料与复习观察条数。用户确认覆盖后才替换当前存档，保留先导出现有记录的入口；预览模式禁止导入，导出使用正式存档。

首版采用完整替换，不做两份存档的奖励合并，防止重复叠加燃料。损坏、未知版本或不一致账本不得静默覆盖有效存档。导入完成后只根据导入记录补齐缺失的合法奖励事件。

## 7. 数据与代码组织

### 7.1 状态设计

当前内部版本为 v4，继续沿用 `tom-phonics-progress-v1`。实际探索字段为 `current`、`transactions`、`stationStep`、`badge`，与课程状态一起提交，不放入逐课归档。全局视觉偏好与轻复习也随完整存档保存；音乐意图、录音和错误提示次数不保存。

以下为后续扩展到通用目的地的模型示意，不是当前类型；尚未实现其中的通用发现数组、交易时间或首次到达日期。新增目的地时需要设计迁移，不能直接替换当前运行结构。

```ts
// 设计示意，具体类型在实施时与现有 Progress 整合。
type SpaceProgress = {
  currentNodeId: string;
  discoveredNodeIds: string[];
  completedMissionIds: string[];
  collectedItemIds: string[];
  firstArrivedAt: Record<string, string>;
  shipLevel: 1;
  transactions: SpaceTransaction[];
};

type SpaceTransaction = {
  eventId: string;
  kind: 'learning_reward' | 'first_travel';
  sourceId: string;
  amount: number; // 收入为正，航行支出为负
  createdAt: string;
};
```

燃料余额由已验证交易求和派生，避免同时维护两个独立余额。事件 ID 不以时间戳生成：阶段奖励按课程与阶段固定，首次航行按目的地固定，例如 `travel:moon:first`。历史交易保存实际金额，调整未来参数不能追溯改写已有余额。

`discovered` 与 `completedMissionIds` 分别表示到达和互动完成。图鉴收藏、商店苹果/宝石和未来建造材料分别管理，不把第一课补给兑换成燃料。

### 7.2 持久化与故障

学习进度、奖励事件与航行状态使用同一个完整存档提交。存储失败不能显示保存成功：学习仍可进行，明显提示进度未可靠保存；航行提交失败时不播放成功抵达反馈，保留之前的有效探索状态并允许重试。

后台通过 SQLite 事务与独立修订号保证共享写入一致；版本过旧时返回冲突、载入后台最新记录并提示重试。客户端与后台均校验先备条件和燃料账本，固定事件去重不变。旧浏览器记录按指纹只迁移一次，原文保留在后台；不同设备旧档合并有效完成，不能叠加余额。当前服务用于受信任局域网中的一名学习者，没有账号与公网防作弊体系。目标 Safari 的触屏、联网与权限仍需真机验证。接口详见[共享存档接口](PROGRESS_API.md)。
