# 单人共享存档接口

本站电脑后台保存唯一的学习存档。网页通过同源 `/api/progress` 访问，不使用浏览器作为正式存储，不需要账号。接口用于同一家庭的受信任局域网；不是公网多用户服务。

## 请求与响应

所有响应使用 JSON 和 `Cache-Control: no-store`。修改请求必须使用 `Content-Type: application/json`；拒绝跨站请求，不开放跨域读写。

| 请求 | 输入 | 成功结果 |
|---|---|---|
| `GET /api/progress` | 无 | `{ revision, progress }`，首次使用返回版本 0 和初始 v4 存档 |
| `PUT /api/progress` | `{ revision, progress }` | 校验整份存档并在事务中比对版本，提交后返回新版本和存档 |
| `POST /api/progress/migrate` | `{ legacy }`，`legacy` 是旧浏览器存档的原始 JSON 字符串 | 校验并合并旧记录，返回后台存档；相同原始记录只迁移一次 |

`revision` 为非负安全整数，是后台写入版本，独立于课程存档内的 `version: 4`。读取后修改须携带对应版本。两台设备同时写入时，只有当前版本可以提交；旧版本返回 HTTP 409 和最新 `{ revision, progress }`，前端载入最新记录并提示重试，不自动重放旧操作。数据库故障不返回保存成功。

普通存档输入及旧存档原文最大 1 MB；请求体最大 2 MB。课次先备条件、草稿、复习和燃料账本复用备份校验。格式错误返回 400，跨站或跨源修改返回 403，过大返回 413，不支持的方法返回 405，存储故障返回 503。错误响应包含 `error`，409 另含 `snapshot`。

## 旧存档迁移

旧键 `tom-phonics-progress-v1` 仅用于读取迁移，之后不再写入浏览器存储。后台在同一事务中记录原始旧档和迁移指纹，已迁移内容不会因再次打开旧浏览器而反复导入。两台设备的旧档分别迁移时保留各课历史完成、去重物品和有效航行扣费，按固定事件重新派生燃料，不叠加两份余额。当前课的草稿采用学习进度较远的记录；后台已有较新记录时不被较早课次覆盖。预览状态不提交后台。

## 保存与同步

开发服务和 `npm run preview` 共用电脑上的 `.data/progress.sqlite`，也可用 `TOM_PHONICS_DATA_DIR` 指定目录。SQLite 事务和版本检查负责并发写入。按用户要求，数据库主文件（含原始迁移记录）随代码提交，表示提交时的快照；提交前暂停服务并完成 WAL 检查点，运行中的 `-wal`、`-shm` 文件不提交。数据库不作为网页静态资源提供。

启动时读取后台，读取成功前不显示可修改的课程。页面可见时每 3 秒检查新版本，重新获得焦点或回到前台时也检查。网络失败时普通学习仅暂留内存并明确提示未保存，页面保持打开后重试；航行、收藏和备份导入必须提交成功才反馈成功。电脑关机或后台停止期间无法可靠保存，不宣称离线持久化。
