## 1. 背景与产品目标

现有课程以字母音教学、自然拼读、拼字游戏与单句口语任务为主。单句问答（如 NPC 提问 “What is this?”，孩子回答 “It's a cat.”）可以练习句型，但缺少多轮交流和真实任务感。

本方案将原来的「口语挑战页」升级为**剧情驱动的互动式英语冒险系统**：孩子在方块宇宙里与 NPC 交谈，做出选择，获取物品，推动剧情与地图进度。

核心目标：

1. **更多真实开口机会**：一次任务完成 3–5 轮以上有意义的交流，而不是只回答一题。
2. **交流有明确目的**：如购物、寻找钥匙、修理飞船、照顾宠物。
3. **与亲子陪学匹配**：由网站负责播放音频、场景和剧情；爸爸负责倾听、示范、鼓励与确认。
4. **与自然拼读并行**：拼读是文字解码训练；对话是听说训练，允许对话中出现孩子尚不能独立拼读、但可以通过听说掌握的词。
5. **开发成本可控**：MVP 不依赖麦克风、语音识别、AI API 或复杂后台；复用状态机和 JSON 配置。

### 不做的事情（MVP）

- 不使用录音、自动评分或声称能够判断孩子发音是否正确。
- 不做 AI 自由聊天；使用可控的分支剧情。
- 不做 3D 开放世界或复杂经济/背包系统。
- 不采用限时答题、扣星星等容易造成挫败的机制。

## 2. 教学原则

- **先听、再说、后点按**：孩子先听 NPC 的音频并口头回应，再由爸爸确认或选择剧情分支；避免退化为默读选项的选择题。
- **任务导向**：每句话都服务于“想完成的事情”，如买苹果、找钥匙。
- **重复但不机械**：高频句型在不同场景复现，人物、道具与回应有所变化。
- **渐进支架**：先完整跟读，再关键词提示，最后不提示自主表达。
- **分开记录技能**：拼读掌握度与口语参与度分别记录；不把孩子是否愿意当场开口作为惩罚性通关门槛。
- **正确反馈要诚实**：没有语音识别时，系统只记录「家长确认已尝试/已完成」，不展示“AI 发音评分 100 分”。

## 3. 核心玩法：NPC 情景对话冒险

### 3.1 一次对话的标准循环

1. 玩家进入场景，观察 NPC、物品和任务目标。
2. NPC 通过**预制音频 + 字幕**提出问题或提示。
3. 孩子**先口头回答**；可点击「再听一次」「给我提示」。
4. 爸爸按「完成这轮练习」；如果是分支节点，孩子选择对应目标物品/行动。
5. NPC 播放与选择对应的下一句，物品/任务状态同步改变。
6. 结束时回顾本次说过的句子，发放游戏奖励。

### 3.2 三档口语帮助

| 模式 | 画面展示 | 适用阶段 |
|---|---|---|
| 跟读模式 | 完整英文句子、跟读音频 | 初学句型 |
| 提示模式 | 图片、关键单词、句型框架（如 `I want a ____.`） | 需要少量帮助 |
| 自主模式 | NPC 问题和场景，不展示目标句子 | 熟悉后复习 |

支持同一任务随时切换帮助等级，**不因使用提示降低基础奖励**。

## 4. 五种可复用的主题场景

| 场景 | 游戏动机 | 典型表达 | 关键互动 |
|---|---|---|---|
| 宇宙商店 | 购买飞船补给 | Hello! / I want an apple, please. / Thank you! | 选择商品→向 NPC 请求→获得道具 |
| 神秘森林 | 根据提示找到钥匙 | Where is the key? / It's under the tree. | 听位置描述→点击场景物品→继续询问 |
| 飞船维修站 | 与机器人共同修飞船 | Can you help me? / Yes, I can. / Here you are. | 选工具→请求帮助→安装零件 |
| 太空小屋 | 照顾方块宠物 | Are you hungry? / I want some water. | 选择食物和道具→回应宠物 |
| 星际遗迹 | 通过交流解谜 | What can you see? / I can see a big robot. | 寻找线索→对 NPC 描述→开启机关 |

五种场景使用相同的对话引擎，只替换资源、节点配置和游戏状态更新。

## 5. MVP 实例：宇宙商店

### 5.1 任务描述

- 任务名称：**宇宙商店：采购飞船补给**
- 剧情：飞船缺少补给，Tom 进入方块村庄，向机器人店主购买一个苹果或一颗能量宝石。
- 推荐时长：单次 5–8 分钟；在 23 分钟情景冒险环节中可重复体验不同分支与复习变式。
- 核心交流目标：打招呼 → 表达需求 → 表示感谢。
- 成功条件：完成三轮口语尝试及对应剧情，不要求自动语言评分。

### 5.2 逐轮脚本

| 轮次 | NPC 音频/字幕 | 孩子的目标表达 | 操作与反馈 |
|---|---|---|---|
| 1 打招呼 | Hello! Welcome to my shop! | Hello! | 爸爸确认尝试→NPC 继续 |
| 2 表达需求 | What do you want? | I want an apple, please. / I want a gem, please. | 孩子先说→选择商品→分支变化 |
| 3 递交物品 | Here is your apple! / Here is your gem! | Thank you! | 爸爸确认→NPC 回应 You're welcome! |
| 结尾 | Have a great trip! | Bye! | 获得对应物品，更新任务进度 |

可追加的进阶分支：NPC 询问 “What color do you want?”，孩子说 “A red one, please.”；只在学过颜色表达后解锁。

### 5.3 页面布局（iPad 横屏）

建议基于约 `1194 × 834 CSS px` 的参考画布响应式适配，避免依赖固定机型：

```text

│ ← 星际地图     宇宙商店 · 任务 02/04          ⭐ 12    🔊 设置      │
├───────────────────────────────────────────┬─────────────────────────┤
│                                           │ 任务提示                │
│     方块村庄 / 柜台 / NPC 机器人           │ 购买飞船补给           │
│                                           │                         │
│     🤖 NPC 对话气泡                        │ 🍎 苹果    💎 宝石      │
│     “What do you want?”                   │                         │
│                                           │ [再听] [提示]          │
│                                           │                         │
├───────────────────────────────────────────┴─────────────────────────┤
│ 🗣 先开口回答，再请爸爸确认        [我说好了] / [选择物品并继续]    │
```

**布局原则：** 场景占主要视觉面积，字幕清晰大字；底部固定主按钮；所有按钮可触屏点按，避免 hover-only 交互；尽量整屏不滚动。

### 5.4 交互状态

- `idle`：场景载入，显示 NPC 与任务。
- `npc_speaking`：播放本句音频并显示字幕。
- `awaiting_speech`：提示孩子回答，可反复播放音频或查看帮助。
- `awaiting_parent_confirm`：爸爸确认孩子已尝试说出本轮内容。
- `awaiting_choice`：如有分支，选择想购买的物品。
- `npc_feedback`：播放对应回应、增加游戏资源。
- `completed`：奖励总结与返回地图。

**防跳过规则：** 默认先完成“孩子口头尝试”确认，再允许进入关键剧情分支；但父母可在必要时直接帮助推进，不把孩子卡在某个节点。

## 6. 五个页面架构中的位置

长期页面职责规划如下。当前项目另有课程总览，第一课对话复用口语视图，奖励回顾在对话页内实现：

1. **星际地图**：任务入口与故事进度。
2. **自然拼读课堂**：学习新音与单词，听读训练。
3. **游戏挑战**：音素合成、听音匹配、拼写方块。
4. **情景对话冒险**（升级）：NPC 多轮交互、支架提示、分支选择、家长确认。
5. **奖励结算**：拼读回顾、口语任务回顾、道具和星球进度。

自然拼读和对话可以使用相同的星球故事线，但教学目标分别配置，避免对话词汇超出已学拼读规则时造成误判。

## 7. 每周 60 分钟课程中的位置

| 环节 | 时长 | 主要内容 |
|---|---:|---|
| 复习 | 5 分钟 | 旧字母音和旧单词 |
| 自然拼读 | 12 分钟 | 新字母音 / 新拼读规律 |
| 拼字游戏 | 10 分钟 | 听音、分音、合音、方块合成 |
| 休息 | 5 分钟 | 起身、喝水、离开屏幕 |
| **情景对话冒险** | **23 分钟** | NPC 交谈、多分支任务、句型复现 |
| 奖励与回顾 | 5 分钟 | 复述几句核心表达、奖励道具 |
| **合计** | **60 分钟** | 依孩子注意力灵活缩短或分段 |

23 分钟不意味着持续紧盯屏幕或连续开口；可以由「5–8 分钟短场景 + 爸爸现实互动 + 再次任务」组合完成。

## 8. 与 48 周课程体系的衔接

在现有 6 大星球自然拼读主线之外，增加独立的**口语交流线**：

- **拼读目标**：能通过所学字母—音素对应关系解码单词。
- **交流目标**：能听懂任务句型并作出口语回应。

每节课配置 1 个情景目标、2–4 个可重复使用的关键表达、1 个游戏任务。示例：

| 阶段 | 对话重点 | 适用场景 |
|---|---|---|
| 周 1–8 | Hello / I'm ... / It's a ... / Thank you | 宇宙商店入门、遇到新朋友 |
| 周 9–16 | I want ... / I have ... / What color ... | 购物、采矿和道具交换 |
| 周 17–24 | Where is ... / It's on/in/under ... | 神秘森林寻宝 |
| 周 25–32 | Can you ... / Yes, I can / I can ... | 飞船修理合作 |
| 周 33–40 | 喜好、需求、简单描述 | 太空小屋、海洋探索 |
| 周 41–48 | 组合使用旧句型、3–5 轮有提示交流 | 星际遗迹与综合任务 |

此表是目标路线而非刚性进度；同一句型需在不同周、不同人物和任务中重复出现。

## 9. 对话引擎与数据模型

建议实现**数据驱动的有限状态/分支对话引擎**。所有对话节点都有稳定的 `id`，剧情通过 `next` 或选项的 `next` 跳转。

## 10. 素材与技术实现

- **前端**：React + TypeScript + 原生 CSS，与现有项目一致。
- **视觉素材**：原创 Minecraft 灵感的 2D 方块场景、NPC、道具和按钮；避免直接使用受版权或商标保护的官方素材。
- **音频**：优先使用统一口音、语速适中的预生成/录制英文音频；每句可重放。音频不应自动在未交互时强制播放。
- **状态保存**：首版使用 `localStorage` 保存当前剧情节点、获得道具和课程完成情况；不保存儿童声音或敏感个人信息。
- **交互**：使用触屏友好的 Pointer Events；不依赖 hover，不要求键盘输入。
- **部署**：静态站点 + HTTPS，适配 iPad Safari。
- **无障碍**：字幕与音频并存；可静音与重放；文字与背景保持足够对比度。

## 11. MVP 验收标准

### 功能

- [ ] iPad 横屏能完整运行宇宙商店场景，无横向溢出、误触和关键按钮遮挡。
- [ ] 至少有 3 轮对话：打招呼、购买、感谢，结尾自然收束。
- [ ] 至少有 2 个有效分支（苹果、宝石），选择后 NPC 回复和奖励一致。
- [ ] NPC 英文音频可点按播放、重复播放，失败时有文字降级反馈。
- [ ] 孩子可先开口，家长可确认后推进，不需麦克风授权。
- [ ] 支持完整句子提示与关键词提示。
- [ ] 退出重进后可继续任务，不会重复发奖励。
- [ ] 结算页能显示本次使用的目标表达和获得物品。

### 亲子体验验证

- [ ] 孩子能独立理解主要按钮与画面目标。
- [ ] 在家长引导下，能完成至少三次真实口头回应。
- [ ] 情景分支能引发“我还想试另一个选择”的兴趣，而非只追求点完。
- [ ] 一段场景控制在约 5–8 分钟，注意力下降时可以随时暂停。
- [ ] 错误/求助不会触发负面评分或惩罚。

## 12. 分阶段实施路线

**阶段 A — 最小可玩原型**

1. 实现场景布局、NPC、气泡、音频与按钮。
2. 实现对话 reducer 和 JSON 读取。
3. 完成宇宙商店的 3 轮对话、2 个分支。
4. 增加家长确认、提示、奖励和断点恢复。

**阶段 B — 教学扩展**

1. 增加森林寻宝、飞船维修两个场景。
2. 接入课程目标，使新句型和旧句型自动穿插。
3. 记录孩子在不同句型上的“独立完成/提示后完成/需要帮助”。
4. 与星球解锁、资源制作、复习任务打通。

**阶段 C — 可选的未来升级**

- 增加更多 NPC、任务剧情和道具系统。
- 如果确有需求，再探索儿童语音识别或受控 AI 对话；需重新评估隐私、成本与识别准确性。

## 13. 关键设计决策（摘要）
