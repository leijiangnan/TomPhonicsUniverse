第一课「对话水晶星」已实现宇宙商店：问候、购买、感谢、告别四轮，苹果和宝石两条分支，可在每轮临时录音回放。第 4、8 课复用飞船复习场景完成 1 轮和 3 轮对话；其余已实现课为配图单句问答。全部口语仍由家长确认，不自动评分。

- 数据使用 `src/data/dialogues/shop.ts` 的类型化配置；转换与恢复使用 `src/lib/dialogue.ts`，未引入状态机库或外部 JSON 加载器。
- 每句点按播放，支持跟读、关键词和自主三档。家长确认购买轮后再选择物品，也可由家长协助推进。
- 当前页面内展示句子回顾和补给，没有独立奖励页、星星总数或复杂背包。苹果和宝石各保存一份，重玩不重复累加。
- 在现有 v4 课程状态中保留可选 `dialogue`，按课程保存。旧版第一课完成记录不回退，未完成者需走完对话并点击点亮按钮。
- 新增 10 段本地合成句子音频，仍待人工校对。浏览器流程验证与真机/亲子验收分别记录，不能互相替代。
- 录音请求及录音期间禁用问题、示范、提示和家长确认，复习课还禁用场景点读；录音结束、失败或离开后释放限制。课堂背景减弱静止、背景音乐暂停，声音面板仍可查看当前声音状态。这些优化不改变对话完成条件。

以下章节保留完整设计方向；其中其他场景、星星奖励、独立结算页、JSON schema 校验及专门播放阶段状态属于后续方案。

## 1. 背景与产品目标

现有课程以字母音教学、自然拼读、拼字游戏与单句口语任务为主。单句问答（如 NPC 提问 “What is this?”，孩子回答 “It's a cat.”）可以练习句型，但缺少多轮交流和真实任务感。

本方案将原来的「口语挑战页」升级为**剧情驱动的互动式英语冒险系统**：孩子在方块宇宙里与 NPC 交谈，做出选择，获取物品，推动剧情与地图进度。

核心目标：

1. **更多真实开口机会**：一次任务完成 3–5 轮以上有意义的交流，而不是只回答一题。
2. **交流有明确目的**：如购物、寻找钥匙、修理飞船、照顾宠物。
3. **与亲子陪学匹配**：由网站负责播放音频、场景和剧情；爸爸负责倾听、示范、鼓励与确认。
4. **与自然拼读并行**：拼读是文字解码训练；对话是听说训练，允许对话中出现孩子尚不能独立拼读、但可以通过听说掌握的词。
5. **开发成本可控**：完成任务不要求麦克风授权；可选录音使用浏览器能力，不接语音识别、AI API 或复杂后台。当前复用类型化配置与 reducer，通用 JSON 引擎保留为后续方案。

### 不做的事情（MVP）

- 第一课录音仅用于本轮临时回放，不上传或保存；不自动评分或声称能够判断孩子发音是否正确。
- 不做 AI 自由聊天；使用可控的分支剧情。
- 不做 3D 开放世界或复杂经济/背包系统。
- 不采用限时答题、扣星星等容易造成挫败的机制。

## 2. 教学原则

- **先听、再说、后点按**：孩子先听 NPC 的音频并口头回应，再由爸爸确认或选择剧情分支；避免退化为默读选项的选择题。
- **任务导向**：每句话都服务于“想完成的事情”，如买苹果、找钥匙。
- **重复但不机械**：高频句型在不同场景复现，人物、道具与回应有所变化。
- **渐进支架**：先完整跟读，再关键词提示，最后不提示自主表达。
- **分开记录技能**：拼读掌握度与口语参与度分别记录；不把孩子是否愿意当场开口作为惩罚性通关门槛。
- **正确反馈要诚实**：没有语音识别时，系统只记录「家长确认已尝试/已完成」，不展示“AI 发音评分 100 分”。

## 3. 核心玩法：NPC 情景对话冒险

### 3.1 一次对话的标准循环

1. 玩家进入场景，观察 NPC、物品和任务目标。
2. NPC 通过**预制音频 + 字幕**提出问题或提示。
3. 孩子**先口头回答**；可点击「再听一次」「给我提示」。
4. 爸爸按「完成这轮练习」；如果是分支节点，孩子选择对应目标物品/行动。
5. 展示与选择对应的下一句，用户点按播放，物品和任务状态同步改变。
6. 结束时回顾本次尝试的句子和已收集补给，再提交水晶星完成；当前没有独立星星奖励或结算页。

### 3.2 三档口语帮助

| 模式 | 画面展示 | 适用阶段 |
|---|---|---|
| 跟读模式 | 完整英文句子、跟读音频 | 初学句型 |
| 提示模式 | 图片、关键单词、句型框架（如 `I want a ____.`） | 需要少量帮助 |
| 自主模式 | NPC 问题和场景，不展示目标句子 | 熟悉后复习 |

支持同一任务随时切换帮助等级，**不因使用提示降低基础奖励**。

### 3.3 提示、录音和声音的设计理由

| 设计决定 | 理由与边界 |
|---|---|
| 保留完整跟读、关键词和自主表达 | 允许家长按当次状态选择支持程度，使用提示不扣奖励；三档帮助不是掌握等级，也不强制按档升级 |
| 先尝试表达，再由家长确认分支 | 让物品选择服务口头交流，而非只点选答案；购买轮确认后才选择物品，家长可以协助，不用自动评分拦住孩子 |
| 录音仅作本轮可选回放 | 提供倾听自身尝试的机会，避免增加账号、上传和儿童声音存档；拒权、不支持或失败时仍可陪练与家长确认 |
| 请求麦克风即暂停播放和确认 | 避免把设备示范混入录音，也避免未结束录音就跳到下一轮；这项互斥不表示已经在真机验证了回声或发音质量 |
| 课堂静态且暂停背景音乐 | 让场景、问题与当前操作保持稳定，教学和录音优先；这是支持专注的设计目标，不是已完成儿童实测的结论 |
| 故事结果复用学习记录 | 第 3 课的地图介绍与驾驶舱安装从已有完成状态派生，不另存物品数量，也不额外发燃料 |

当前 `TemporaryRecording.tsx` 管理临时回放、迟到媒体流及离开清理，`audio.ts` 的独占锁阻止旁路播放，`backgroundMusic.ts` 让音乐退让。视觉和声音是独立控制，系统减少动态效果不自动静音；完整矩阵见 [PRD 4.4](PRD.md#44-背景可见性与专注的取舍) 与 [4.5](PRD.md#45-声音入口与播放优先级)。

## 4. 五种可复用的主题场景

| 场景 | 游戏动机 | 典型表达 | 关键互动 |
|---|---|---|---|
| 宇宙商店 | 购买飞船补给 | Hello! / I want an apple, please. / Thank you! | 口头请求→家长确认→选择商品→获得补给 |

## 5. MVP 实例：宇宙商店

### 5.1 任务描述

- 任务名称：**宇宙商店：采购飞船补给**
- 剧情：飞船缺少补给，Tom 进入方块村庄，向机器人店主购买一个苹果或一颗能量宝石。
- 推荐时长：单次 5–8 分钟；在 23 分钟情景冒险环节中可重复体验不同分支与复习变式。
- 核心交流目标：打招呼 → 表达需求 → 表示感谢 → 告别。
- 成功条件：家长确认四轮尝试，完成分支与句子回顾后点击点亮；不要求录音、自动识别或发音评分。旧版已完成记录继续有效。

### 5.2 逐轮脚本

| 轮次 | NPC 音频/字幕 | 孩子的目标表达 | 操作与反馈 |
|---|---|---|---|
| 1 打招呼 | Hello! Welcome to my shop! | Hello! | 爸爸确认尝试→NPC 继续 |
| 2 表达需求 | What do you want? | I want an apple, please. / I want a gem, please. | 先尝试表达并由家长确认，再选择商品 |
| 3 递交物品 | Here is your apple! / Here is your gem! | Thank you! | 爸爸确认→NPC 回应 You're welcome! |
| 4 告别 | You're welcome! Have a great trip! | Bye! | 家长确认后进入本页回顾，完成后点亮水晶星 |

后续可设计颜色等进阶分支，需先核对听说先备内容；当前没有该分支或自动解锁条件。

### 5.3 页面布局（iPad 横屏）

建议基于约 `1194 × 834 CSS px` 的参考画布响应式适配，避免依赖固定机型：

```text
┌─────────────────────────────────────────────────────────────────────┐
│ ← 星球地图    第 1 课 · 对话水晶星    声音与音乐 / 全屏 / 家长    │
├─────────────────────────────────────────────────────────────────────┤
│ 宇宙商店 · 买一份补给                                      2 / 4 │
│ 🤖 NPC 气泡：What do you want?                                  │
│                         🍎 苹果    💎 宝石                       │
│               [跟着说] [关键词] [自己说]                         │
│                  示范句子 / [我来说]                            │
├─────────────────────────────────────────────────────────────────────┤
│ 家长确认本轮尝试      [家长帮我说] / [说好啦，家长确认]           │
└─────────────────────────────────────────────────────────────────────┘
```

**布局原则：** 一屏一个当前任务，场景占主要面积，不设独立任务侧栏或星星总数；提示和示范在本场景内，确认操作放在底部。按钮至少 48 × 48 CSS px，不依赖 hover；横屏优先保证主操作可见，窄屏允许正常滚动。具体尺寸以 PRD 和真机检查为准，不把草图当作固定像素布局。

### 5.4 交互状态

当前持久化的是 `greeting / request / thanks / goodbye / completed` 节点、提示档、家长确认、分支和已收集物品。麦克风请求、录音、回放地址和播放中的状态只在本轮内存中使用。以下专门的播放阶段枚举为后续引擎建模示意，并非当前已保存字段：

- `idle`：场景载入，显示 NPC 与任务。
- `npc_speaking`：播放本句音频并显示字幕。
- `awaiting_speech`：提示孩子回答，可反复播放音频或查看帮助。
- `awaiting_parent_confirm`：爸爸确认孩子已尝试说出本轮内容。
- `awaiting_choice`：如有分支，选择想购买的物品。
- `npc_feedback`：播放对应回应、增加游戏资源。
- `completed`：奖励总结与返回地图。

**防跳过规则：** 默认先完成“孩子口头尝试”确认，再允许进入关键剧情分支；但父母可在必要时直接帮助推进，不把孩子卡在某个节点。

## 6. 五个页面架构中的位置

长期页面职责规划如下。当前项目另有课程总览，第一课对话复用口语视图，奖励回顾在对话页内实现：

1. **星际地图**：任务入口与故事进度。
2. **自然拼读课堂**：学习新音与单词，听读训练。
3. **游戏挑战**：音素合成、听音匹配、拼写方块。
4. **情景对话冒险**（升级）：NPC 多轮交互、支架提示、分支选择、家长确认。
5. **奖励结算**：拼读回顾、口语任务回顾、道具和星球进度。

自然拼读和对话可以使用相同的星球故事线，但教学目标分别配置，避免对话词汇超出已学拼读规则时造成误判。

## 7. 每周 60 分钟课程中的位置

| 环节 | 时长 | 主要内容 |
|---|---:|---|
| 复习 | 5 分钟 | 旧字母音和旧单词 |
| 自然拼读 | 12 分钟 | 新字母音 / 新拼读规律 |
| 拼字游戏 | 10 分钟 | 听音、分音、合音、方块合成 |
| 休息 | 5 分钟 | 起身、喝水、离开屏幕 |
| **情景对话冒险** | **23 分钟** | NPC 交谈、多分支任务、句型复现 |
| 奖励与回顾 | 5 分钟 | 复述几句核心表达、奖励道具 |
| **合计** | **60 分钟** | 依孩子注意力灵活缩短或分段 |

23 分钟不意味着持续紧盯屏幕或连续开口；可以由「5–8 分钟短场景 + 爸爸现实互动 + 再次任务」组合完成。

## 8. 与 48 周课程体系的衔接

在现有 6 大星球自然拼读主线之外，增加独立的**口语交流线**：

- **拼读目标**：能通过所学字母—音素对应关系解码单词。
- **交流目标**：能听懂任务句型并作出口语回应。

每节课配置 1 个情景目标、2–4 个可重复使用的关键表达、1 个游戏任务。示例：

| 阶段 | 对话重点 | 适用场景 |
|---|---|---|
| 周 1–8 | Hello / I'm ... / It's a ... / Thank you | 宇宙商店入门、遇到新朋友 |
| 周 9–16 | I want ... / I have ... / What color ... | 购物、采矿和道具交换 |
| 周 17–24 | Where is ... / It's on/in/under ... | 神秘森林寻宝 |
| 周 25–32 | Can you ... / Yes, I can / I can ... | 飞船修理合作 |
| 周 33–40 | 喜好、需求、简单描述 | 太空小屋、海洋探索 |
| 周 41–48 | 组合使用旧句型、3–5 轮有提示交流 | 星际遗迹与综合任务 |

此表是目标路线而非刚性进度；同一句型需在不同周、不同人物和任务中重复出现。

### 9.3 关键运行时状态

```ts
type DialogueRuntime = {
  sceneId: string;
  nodeId: string;

         'awaiting_parent_confirm' | 'awaiting_choice' |
         'npc_feedback' | 'completed';
  hintLevel: 'full' | 'keyword' | 'none';
  selectedChoiceId?: string;
  completedNodeIds: string[];
  grantedRewardEventIds: string[];
};
```

不需要第一版就引入专门的状态机库；可先通过 React reducer 实现，后续复杂度增加再迁移。

## 10. 素材与技术实现

- **前端**：React + TypeScript + 原生 CSS，与现有项目一致。
- **视觉素材**：原创 Minecraft 灵感的 2D 方块场景、NPC、道具和按钮；避免直接使用受版权或商标保护的官方素材。
- **音频**：优先使用统一口音、语速适中的预生成/录制英文音频；每句可重放。音频不应自动在未交互时强制播放。
- **状态保存**：首版使用 `localStorage` 保存当前剧情节点、获得道具和课程完成情况；不保存儿童声音或敏感个人信息。
- **交互**：使用触屏友好的 Pointer Events；不依赖 hover，不要求键盘输入。
- **部署条件**：静态站点；真实录音需要 HTTPS 或 localhost 等安全上下文及麦克风授权。当前本地可运行不代表已经发布正式 HTTPS 网站或完成 iPad Safari 验收。
- **无障碍**：字幕与音频并存；可静音与重放；文字与背景保持足够对比度。

## 12. 分阶段实施路线

**阶段 A — 当前已实现原型，人工验收待完成**

1. 实现场景布局、NPC、气泡、音频与按钮。
2. 使用类型化脚本配置和 reducer，通用 JSON 读取与校验尚未实现。

**阶段 C — 可选的未来升级**

- 如果确有需求，再探索儿童语音识别或受控 AI 对话；需重新评估隐私、成本与识别准确性。

## 13. 关键设计决策（摘要）

- **首课以多轮分支冒险示范，其他已实现课按配置保留单句或场景问答。**
- **坚持父亲陪学，支持本轮临时录音回放，不做 AI 评分。**
- **对话是独立的听说课程线，与 48 周自然拼读路线并行。**
- **当前用类型化脚本与 reducer 复用行为，通用 JSON 引擎是后续方向。**
- **优先验证商店任务是否易理解、愿意表达，再决定新增场景；不能用代码完成代替亲子实测。**
